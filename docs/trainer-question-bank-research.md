# Research: trainer question bank

Дата ресерча: 2026-05-11.

Цель исходного ресерча: заменить выдуманные формулировки на банк, основанный на реальных открытых interview-question источниках.

Текущий статус: полностью заполнены все темы `Frontend Developer / Junior`, `Frontend Developer / Middle` и `Frontend Developer / Senior` — по 20 вопросов. Остальные специальности и грейды пока пустые.

## Использованные источники

| Источник | Лицензия | Что взято для банка |
| --- | --- | --- |
| [Front End Interview Handbook](https://github.com/yangshun/front-end-interview-handbook) | MIT | JavaScript, DOM, browser, frontend system design, формат frontend-интервью |
| [Lydia Hallie JavaScript Questions](https://github.com/lydiahallie/javascript-questions) | MIT | JavaScript edge cases, promises, closures, coercion, runtime behavior |
| [Sudheer Jonna ReactJS Interview Questions](https://github.com/sudheerj/reactjs-interview-questions) | MIT | React, hooks, state, rendering, performance |
| [Tech Interview Handbook](https://github.com/yangshun/tech-interview-handbook) | MIT | структура BigTech-интервью, ожидания по грейдам, system design prep |
| [The System Design Primer](https://github.com/donnemartin/system-design-primer) | CC BY 4.0 | scalability, caching, queues, databases, availability, system design trade-offs |
| [Node.js Interview Questions](https://github.com/aswanth6000/nodejs-interview-questions) | MIT | Node.js runtime, event loop, streams, clustering, security |
| [Awesome Interviews](https://github.com/DopplerHQ/awesome-interview-questions) | CC0 | навигация по Docker, Postgres, SQL, Redis, Node.js и frontend question banks |

## Правила переноса

- При повторном наполнении формулировки нужно адаптировать на русский и приводить к MCQ-формату с 4 вариантами ответа.
- Массовое дословное копирование закрытых, коммерческих и неясно лицензированных банков не используется.
- Вопросы оставлены без выдуманных вводных вроде "на секции", "команда спорит" или "production incident".
- Junior проверяет практические основы и типичные баги.
- Middle добавляет диагностику, эксплуатацию и безопасные production-исправления.
- Senior добавляет highload, p99, memory leaks, concurrency, consistency, recovery и архитектурные компромиссы.
